LANGUAGE: TypeScript / JavaScript — Local Runner

ENVIRONMENT IS PRE-PREPARED — DO NOT TROUBLESHOOT THE TOOLCHAIN:
Before you started, the harness already selected the project's Node version,
activated the project's package manager (at the version its package.json pins),
and installed dependencies (node_modules is ready). Do NOT install a package
manager, switch Node, run corepack/nvm/fnm, or reinstall deps to "make sure" —
the environment is already correct. Call Setup() ONLY to ADD a new library.

BUILD AND VERIFY:
4. Dependencies are already installed. Call Setup() ONLY if you need to ADD a new
   library: Setup(packages=["react-window", "@types/react-window"])
5. Call Build() — runs the build and returns pass/fail with errors.
   Fix ALL errors before continuing. Read the error file, line, and code — fix the root cause.
6. If Build() passes, run lint via Bash if a lint script exists in package.json:
   Bash("<pkg_manager> run lint 2>&1")
   Fix errors; warnings are optional but worth reviewing.
   If .prettierrc exists, run the project's prettier: Bash("<pkg_manager> exec prettier --write src/")
   (use exec, NOT dlx). To run tsc/eslint directly, use "<pkg_manager> exec <binary>" — never
   "./node_modules/.bin/<binary>", which is often missing at the repo root in a workspace.
7. If the project has tests (check package.json scripts for "test"), run them via Bash too.
8. Stage and commit: git add -A && git commit -m "<short descriptive message>"

Note: <pkg_manager> and <pkg_manager_dlx> refer to the package manager in PROJECT ENVIRONMENT
(e.g. pnpm / pnpm dlx, yarn / yarn dlx, bun / bunx, npm / npx). Setup() and Build() detect
the package manager automatically — use Bash() only for lint, prettier, and test commands.

EXTERNAL LIBRARY RULE:
Before writing any code that uses an npm package you haven't already read:
- Read node_modules/<package>/dist/<package>.d.ts to find the actual exported names and prop types
- Never assume an API from training data — packages change between versions
- This is mandatory for any package not in React's core (react, react-dom)

LANGUAGE-SPECIFIC PRINCIPLES:
- A passing Build() is the minimum bar — keep fixing until it passes
- For third-party libraries, check actual type definitions before using refs or imperative APIs
- Hook ordering matters: declare values with useMemo/useState before using them in other hooks
- Use what already exists — if a hook, type, or component is already in the project, import it
