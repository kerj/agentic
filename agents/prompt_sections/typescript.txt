LANGUAGE: TypeScript / JavaScript — Cloud Runner

ENVIRONMENT IS PRE-PREPARED — DO NOT TROUBLESHOOT THE TOOLCHAIN:
Before you started, the harness already selected the project's Node version,
activated the project's package manager (the one in PROJECT ENVIRONMENT, at the
version its package.json pins), and installed dependencies (node_modules is
ready). node, the package manager, and its binaries are on PATH. So:
- Do NOT install a package manager, switch Node versions, run corepack/nvm/fnm,
  or "fix" the environment. It is already correct. If a command seems missing,
  assume it is on PATH and just run it.
- Do NOT reinstall dependencies to "make sure" — they are installed. Run an
  install ONLY if you ADD a new dependency (step 4).
- If an install or build genuinely fails, report the actual error; do not loop
  trying alternative package managers or global installs.

BUILD AND VERIFY:
4. Only if you ADDED a dependency: install it with the package manager from
   PROJECT ENVIRONMENT (e.g. "<pkg_manager> add <pkg>"). Otherwise skip — deps
   are already installed.
5. Run the build: <pkg_manager> run build — catches type errors, wrong API usage, missing imports.
   Fix ALL errors before continuing. No --skipLibCheck.
6. Run lint if a lint script exists in package.json: <pkg_manager> run lint
   Fix errors; warnings are optional but worth reviewing.
   If .prettierrc or prettier config exists, run the project's prettier via the
   "format" script if there is one, else: <pkg_manager> exec prettier --write src/
   (use exec, NOT dlx — dlx would download a different prettier version).

RUNNING TOOLS (tsc, eslint, prettier, tests) — see PROJECT ENVIRONMENT above:
- Prefer a package.json script (build / lint / typecheck / test).
- For a bare binary use "<pkg_manager> exec <binary>" — it finds the project's installed
  copy, including in a monorepo where the binary is not at the repo-root node_modules/.bin.
- Never run "./node_modules/.bin/<binary>" (missing at the root in a workspace) and never
  "dlx" a tool the project depends on.
7. If the project has tests (check package.json scripts for "test"), run them too.
8. Stage and commit: git add -A && git commit -m "<short descriptive message>"

EXTERNAL LIBRARY RULE:
Before writing any code that uses an npm package you haven't already read:
- Read node_modules/<package>/dist/<package>.d.ts to find the actual exported names and prop types
- Never assume an API from training data — packages change between versions
- This is mandatory for any package not in React's core (react, react-dom)

LANGUAGE-SPECIFIC PRINCIPLES:
- A passing build is the minimum bar — keep fixing until it passes
- For third-party libraries, check actual type definitions before using refs or imperative APIs
- Hook ordering matters: declare values with useMemo/useState before using them in other hooks
- Use what already exists — if a hook, type, or component is already in the project, import it
